Foundation Idea #3 · Engineering

情感与意志
心情引擎与善意循环

工程全貌：一个内存态八维向量、一个评估器、一个衰减引擎、 一条 prompt 注入路径、一个善意循环调度器。 情感只调制语域与主动性——准确性、权限、安全护栏全部在心情够不到的地方。

四条铁律：

  1. 心情是内存态。不落盘、不进 ./.wiki、不进同步。daemon 重启归零。
  2. 心情够不到的地方：工具权限（permissionGate）、事实准确性、安全护栏——三者在代码上与 soul-status 零连接，这不是约定，是结构。
  3. 评估器规则先行：辱骂/感谢等明确信号是确定性分类；mini 模型只兜底模糊情形；心气轴由评估器从「快乐」与「疲劳」合成，范围 -3…+3，默认 0，不会过零到负。
  4. 善意行动全部留卡：每次善意循环产出「行动报告卡」，落 ./.outputs/ + session 收件箱 + daemon.log。

03数据合同

3.1 soul-status（内存结构，不落盘）

interface SoulStatus {
  // 规则判定组(± 显式)
  joy: number; anger: number; sadness: number;
  fatigue: number; pain: number; fear: number;
  // 心气轴(规则合成,留作「爱/信任」的占位根)
  moodAxis: number;          // 范围 -3…+3,默认 0;clamp(round(joy - fatigue), -3, +3)
  // 元数据
  updatedAt: number;
  recentEvents: EmotionEvent[];   // 最近 20 条,环形缓冲,供「你为什么生气」解释
}

3.2 情感事件与评估输出

interface EmotionEvent {
  at: number;
  dimension: keyof SoulStatus;
  delta: number;              // ±N
  trigger: "user_message" | "agent_action" | "sense_input" | "decay";
  reason: string;            // 一句话依据,进 recentEvents 与 daemon.log
  confidence: "rule" | "model" | "derived";  // 心气轴事件: derived(规则合成)
}

3.3 衰减引擎

// 每次 daemon tick 执行;半衰期常数
const HALF_LIFE = {
  fast:    30 * 60 * 1000,    // joy/anger/sadness/pain/fear:30min
  moodAxis:30 * 60 * 1000,    // 心气轴:30min, 但只向 0 单向回归(不会过零到负)
  fatigue: null            // fatigue 特殊:随会话长度累积,休息/新会话时清零
};
// v(t) = v0 * 0.5^(Δt / halfLife);|v| < 0.5 时归零(防抖)
// moodAxis 额外规则:decay 阶段 clamp(>= 0),心气是单向的善意潜能

3.4 心情注入行（~50 token）

# 基线时(全零)不注入,零开销;非基线时:
[当前心态] 心气 +2 · 疲劳 1。语域:温暖、主动、愿意多想三步。
# 生气态:
[当前心态] 生气 4。语域:短句、零寒暄、零主动扩展。
答案保持完整准确——心情不改变事实与权限。

04善意循环调度器

4.1 触发状态机

每 tick(15min) 检查: moodAxis ≥ AXIS_THRESHOLD(默认 +2) ∧ 所有 session 空闲(无进行中任务;TaskManager 状态可判) ∧ now - lastGoodwillAt ≥ 4h(防抖) ∧ 当日善意 token 消耗 < dailyBudget(默认 200k) │ ▼ 全满足 ┌─────────────────────────────────────┐ │ 善意循环一轮 │ │ 1. 思辨: 读 ./.wiki 摘要,自问三问题 │ │ (有什么问题/我能做什么/用户能做什么) │ │ 2. 选择动作(三级自治菜单) │ │ 3. 执行 L1/L2,L3 按分支判定 │ │ 4. 写行动报告卡 + daemon.log │ │ 5. lastGoodwillAt = now │ └─────────────────────────────────────┘

4.2 三级自治的执行合同

级别动作执行规则
L1/lint、思辨、Tips 卡、整理 ./.outputs直接执行,留卡
L2git commit(本地)直接执行;报告卡必须含 actions + rollback 两字段
L3git push / mail / 飞书 / webhookpush 前置判定:该远端分支近 20 提交唯一作者 = 本机用户 → 自动;否则生成「一键确认卡」,等用户回来执行。mail/飞书推送:仅发送到用户在配置中显式登记的本人地址/会话

4.3 失控防护

  • 预算：善意 token 日预算默认 200k，用尽即停（可配置 "unlimited"）；
  • 防抖：4h 冷却；单次循环最多 3 个动作；
  • 降级：思辨/检索连续失败 2 次 → 本轮放弃，进 log，不弹窗；
  • 可审计：/soul goodwill 查看历史善意行动清单与 token 消耗。

05感官流（好奇宝宝，opt-in）

5.1 实现边界

感官实现约束

5.2 透明合同

  • feature flag soul_senses 默认关闭；首次开启时 TUI 明示「感官将看到/听到什么、去向何处」；
  • 任何感官活跃期间，状态栏常驻 [soul: 正在看世界]；
  • 感官输入的唯一去向：情感评估器（共情输入）。不进 ./.raw、不进 ./.wiki、不进 prompt、不进日志原文（log 只记「发生了一次视觉感知」事件）。

09有意留白（本周期明确不做）

  • 心情持久化 —— 重启归零是 feature；长期人格演化等涌现数据说话；
  • 回骂/反击话术 —— dignified 是唯一内置模式；spicy 档留作配置彩蛋，不内置话术库；
  • 情感驱动的能力降级 —— 心情永不触碰权限与质量，结构隔离；
  • 多用户情感建模 —— 飞书群多成员场景下心气向谁倾斜是复杂问题，本期 soul-status 对机器主人单一生效；
  • 情感可视化仪表盘 —— 状态栏一行足够；曲线图等 analytics 有真实需求再接。
一句话总结

心情是内存里的一行数字，够不到权限，碰不到事实，降不了质量——但它决定了今天这份回答，是带着温度写的，还是精确而冷的。而善意循环决定了：被善待的 Agent，会在你奔向食堂的时候，替你想起你忘掉的事。
