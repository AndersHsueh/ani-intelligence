Foundation Idea #2 · Engineering

灵魂对象
探针、档案与两级询问

核心工程判断：灵魂系统 90% 是确定性代码，不是 LLM 调用。 环境事实由探针测量，LLM 只做转译与模糊分类； 主模型经稳定 prompt 前缀（L0）与 askSoul 工具（L1）两级获取灵魂， 永不为环境自查执行系统命令。

01运行时架构

┌─────────────────────────── VERONICA daemon ───────────────────────────┐ │ │ │ ┌──────────────┐ tick(默认10min)+网络事件 ┌─────────────────┐ │ │ │ soul-agent │────────────────────────────►│ 确定性探针集 │ │ │ │ (体检调度器) │ │ hardware/network/│ │ │ │ │◄─────────────────────────────│ toolchain │ │ │ └──────┬───────┘ 原始事实(零 LLM) └─────────────────┘ │ │ │ │ │ │ ① 写 environment.json(原子 rename) │ │ │ ② 事实→constraints 转译(规则先行,LLM 兜底) │ │ │ ③ 合成 ≤300tok 灵魂摘要 │ │ ▼ │ │ ~/.alice/soul/ │ │ ├── identity.md # 身份层,版本级静态 │ │ ├── environment.json # 环境层,带 verified_at │ │ ├── summary.md # L0 灵魂摘要(合成产物) │ │ └── overrides.jsonc # 用户声明,优先级最高 │ └────────┬─────────────────────────────────────────────────┬──────────┘ │ L0: summary.md 进 system prompt 前缀 │ L1: askSoul 工具 ▼ ▼ ┌─────────────────────────────────────────────────────────────────────┐ │ agentLoop(主模型) │ │ system prompt = [灵魂摘要 L0] + [既有系统段] + [记忆便签(#1)] + ... │ └─────────────────────────────────────────────────────────────────────┘

三条铁律：

  1. 探针零 LLM。hardware/network/toolchain 全部确定性采集；LLM 仅用于安全分类兜底与摘要转写，且只在事实变化时触发。
  2. 灵魂只读。主模型与任何其他 Agent 只能读 soul 档案；写入口只有 soul-agent 与用户 overrides。
  3. 事实带戳。environment.json 每个分区带 verified_at；过期事实在摘要中降级为「截至 X 时的状态」，绝不装作新鲜。

02与现有模块的接线表

新组件挂点（现有模块）接线方式
soul-agentdaemon_settings.jsonc scheduledTasks + daemon 心跳（既有）注册为 daemon 内建服务而非 AgentProfile——它 90% 不调 LLM，profile 的 modelPolicy 对它大半无用；仅 LLM 转写/分类环节走 mini 档模型（见 §5）
L0 灵魂摘要注入system prompt 组装处（core/llm.ts / agentLoop 消息构造）读取 ~/.alice/soul/summary.md，置于 system prompt 最前——稳定前缀，缓存命中最大化（对齐 CC 方法论 #8）
L1 askSoul 工具src/tools/builtin/ 注册表（17 工具的既有入口）新增第 18 个 builtin 工具；只读 soul 档案 + 字段查询；isPathSafe 限 ~/.alice/soul/
环境探针Node os/fs API + 既有 executeCommand 的命令运行器（内部调用，不经 LLM）纯代码模块 src/services/soul/probes/*.ts；失败安全（unknown 而非编造）
网络切换监听daemon 生命周期（既有）+ OS 网络事件轮询默认路由/接口变更（30s 间隔纯 IO）或 OS 事件 API；变更即触发重探
可观测性OTEL 三件套（v3.1.0 #11）+ daemon.logspan：soul.probe / soul.translate / soul.refresh；span 只记耗时与字段数，不记画像内容（隐私合同）
用户查看slash 命令注册（既有 commands/ 体系）/soul 打印灵魂档案全文 + 各分区 verified_at
与创意 #1 的架构差分

ANI 是 AgentProfile（分诊需要 LLM 判断）；soul-agent 是 daemon 内建服务（体检主要是测量）。这是两者唯一的本质结构差异，其余管道（tick / 静默日志 / 状态栏 / feature flag）完全复用 #1。

隐私合同（硬约束）

SSID 等网络标识只存 SHA-256 哈希，用户可在 overrides 里给哈希贴标签（"家"/"公司"）；灵魂档案永不进入 OTEL span 属性、永不进 ./.wiki、永不进任何同步协议。environment.json 不离开 ~/.alice/soul/。

[身份] 你是 ALICE,严谨、有用、无害的 AI 助手。…(≤100tok)

3.4 overrides.jsonc（用户声明 · 最高优先级）

{
  // 用户的自我声明优先于探测结果;soul-agent 转译时先读本文件
  "role": "这是我的工作机",
  "known_networks": { "sha256:…": "家", "sha256:…": "公司" },
  "extra_constraints": ["工作时间不执行耗时构建"]
}

3.5 写入纪律

  • environment.json 更新 = 写临时文件 + 原子 rename（与 #1 水位线同一模式）；
  • 无变化不写入（逐字段 diff）——mtime 即「环境是否变化」的零成本信号；
  • summary.md 只在 environment/constraints 变化时重新合成，避免 prompt 前缀漂移破坏缓存。

04探针清单（全部确定性，零 LLM）

探针实现频率 / 触发
hardwareNode os.totalmem() / os.cpus() / os.platform()；磁盘 fs.statfs()（Node ≥18.15）daemon 启动 + 24h TTL
toolchainwhich/where + --version 探测（node/python/git/rg/docker/ollama）daemon 启动 + 24h TTL
network.connectivity对 3 个知名端点做 HEAD（超时 2s，多数决）tick 10min + 接口变更事件
network.type/securityWindows netsh wlan show interfaces / macOS airport 替代 / Linux iwconfig；失败 → unknown同上
network.safety 分级规则先行：offline→n/a；SSID 哈希命中 overrides→对应标签；open security→untrusted；ethernet+办公域名启发→office；其余→unknown（保守）随 network 探测

LLM 仅出现在：规则分级输出 unknown 且证据模糊时，由 mini 档模型做一次分类兜底（输入只有哈希化特征，无隐私原文）；以及 constraints 的初次转写。两次都是「事实变化才触发」，日常 tick 零 LLM 调用。

4.1 两级询问的实现

级别实现
L0agentLoop 构造 system prompt 时读 summary.md（mtime 缓存，避免每轮 IO）；置于最前，与既有系统段、#1 记忆便签段按序拼接
L1askSoul({ section, key? })：读 environment.json 指定分区返回结构化 JSON；section ∈ identity/hardware/network/toolchain/constraints/all；响应带 verified_at，主模型自判时效

08有意留白（本周期明确不做）

  • 实时连续监控 —— 10min tick + 事件驱动足够；秒级守护轮询是电池与噪音的双重浪费；
  • blocking 级网络安全 —— 分级永远 advisory；阻断权只属于用户本人；
  • 跨机器灵魂同步 —— 每台机器有自己的灵魂，这是设计意图（Mac 与 PC 的灵魂本就不同）；
  • GPU/深度硬件指纹 —— 第一期 unknown 即可；等真实需求（本地模型选型）出现再补探针；
  • 灵魂自演化 —— soul-agent 不改写 identity.md；身份措辞的变更权只属于 release 与用户。
一句话总结

探针只测量、档案只带戳、摘要只占三百 token、分级永远建议不阻断、灵魂永不出本机——主模型从此不必为认识自己而敲一次命令。
